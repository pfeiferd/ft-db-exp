# The human genome, so that the LCA update sees it.
#
# `cv' is applied to human saliva (data/fastq/saliva_real.txt), where human DNA is the bulk of the
# sample. Genestrip's LCA update only pushes a k-mer above a viral taxon if it knows of another
# organism carrying it, and the category `viral' of categories.txt does not include the host. Without
# this entry every k-mer a virus shares with the human genome -- endogenous retroviral sequence,
# integrated herpesvirus, and whatever host contamination the viral assemblies carry -- stays stored
# under its virus and turns human reads into viral hits.
#
# 9606 must NOT appear in taxids.txt: the taxid here declares whose genome the file is, so that the
# LCA update can account for it, not that the database should store its k-mers. Listing it there too
# would put the whole human genome into the database.
#
# The file itself is declared in common/fasta/downloads.txt and is shared with the other projects
# that need it, so it is downloaded once rather than per project.
#
# DISABLED ON 2026-10-07 on Daniel's instruction, so that `cv' accounts for no host that the
# KrakenUniq and Kraken 2 databases of Table 9 cannot account for too. Re-enable by removing the
# `#' below; the entry then takes effect on the next `db'/`ftdb' generation and on nothing before it.
#
# Measured before disabling it, so that the next reader need not repeat it: a `match' run of the
# current `cv' over 10 million reads of SRR5571991 puts *zero* reads at root. The host entry
# therefore diverts no read at all, and removing it does not close the 0.28 to 0.42 percentage point
# gap between `cv' and `cv_ku' on the saliva runs. What does account for that gap is `maxDust=500'
# from ../../config.properties: it drops 102,354 distinct 31-mers from these 19,018 viral genomes,
# and 0.462 % of the saliva reads carry one of them.
#
