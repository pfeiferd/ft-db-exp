# Real Oxford Nanopore SHOTGUN metagenomes of the lower respiratory tract, from ENA study
# PRJEB30781 -- the clinical data the strepto project is applied to.
#
#   Charalampous T, Kay GL, Richardson H, Aydin A, Baldan R, Jeanes C, Rae D, Grundy S, Turner DJ,
#   Wain J, Leggett RM, Livermore DM, O'Grady J (2019): "Nanopore metagenomics enables rapid
#   clinical diagnosis of bacterial lower respiratory infection." Nat Biotechnol 37:783-792.
#   https://doi.org/10.1038/s41587-019-0156-5   (PMID 31235920)
#
# WHY THIS STUDY AND NOT ONE OF THE MANY OTHERS. It is shotgun, not metabarcoding. Every run in the
# project is declared OXFORD_NANOPORE / WGS / METAGENOMIC / RANDOM PCR on "human lung metagenome"
# (verified against the ENA portal API on 2026-08-19), so the reads cover whole genomes rather than
# one rRNA locus. That matters here more than anywhere else in this paper: a 16S amplicon carries
# almost no k-mer that separates S. pneumoniae from S. mitis or S. oralis -- their 16S genes are
# ~99 % identical -- so an amplicon run cannot show a refinement gain even in principle. Practically
# all published clinical Nanopore work on respiratory samples is targeted or amplicon-based; this is
# the study that is not.
#
# The host DNA is removed by the study's saponin differential-lysis protocol before sequencing,
# which is why runs of a few tens of thousands of reads are already microbially informative.
#
# WHAT IS IN HERE. The 83 clinical samples only:
#
#   P1  .. P40                 the pilot pipeline, 40 samples
#   S1  .. S41 (+2 undepleted) the streamlined pipeline, 43 runs
#
#   83 runs, 2,271,441 reads, mean read length about 2.7 kbp.
#
# Deliberately NOT listed, though they are in the same ENA study:
#
#   * the 24 limit-of-detection runs (E. coli / S. aureus spiked at 1e3..1e5 CFU/ml into low- and
#     high-background sputum). They are a defined-composition dilution series and would make a
#     separate experiment on sensitivity, not on refinement -- neither spiked organism is a
#     Streptococcus.
#   * the 6 process extraction negatives, which are in strepto_lri_neg.txt beside this file.
#
# WHICH RUN IS WHICH SAMPLE. The keys below are the study's own sample names, and they are not a
# guess: the ENA metadata carries them in `sample_alias', one per run. (The sample *title* says only
# which pipeline was used, which is what an earlier version of this note mistook for the whole of the
# metadata.) All 83 assignments were checked against the portal API on 2026-08-24 and every one of
# them agreed:
#
#   curl "https://www.ebi.ac.uk/ena/portal/api/filereport?accession=PRJEB30781\
#         &result=read_run&fields=run_accession,sample_alias&format=tsv"
#
# GROUND TRUTH. The reference standard is not in the ENA metadata; it is in the paper's Table 1
# (pilot cohort) and Table 2 (optimised cohort), one row per sample with the organism routine
# microbiology grew beside the one the study's own pipeline reported. It is transcribed in
# data/projects/strepto/ground_truth.csv, where the two are kept apart, since only the first is a
# standard and the second is a comparator.
#
# What that standard can and cannot settle. It names the *pathogen* of a sample, not its contents:
# a sputum sample always carries oral streptococci, and the reference is silent about them. A call
# of, say, `Streptococcus sp. oral taxon 431' on a sample whose reference reads `H. influenzae' is
# therefore not refuted by it -- it is merely outside what the reference speaks about. Only the six
# samples with a culture-confirmed Streptococcus (P3, P28, P30, P33, P36 and P40, all of them in the
# pilot cohort) can decide a streptococcal call outright; the seven of the optimised cohort rest on
# the study's pipeline alone. Where the reference names no Streptococcus at all, these runs are what
# the tick and saliva runs are in this paper -- real data without ground truth, to be read with the
# estimator of Section "Estimating the gain without ground truth".
#
# This is an ordinary Genestrip fastq map, so `fastqdownload' fetches every entry whose second
# column is a URL. With -ll the files land in data/fastq named after their key, i.e.
# data/fastq/P1.fastq.gz .. S41.fastq.gz:
#
#   mvn exec:exec@fastqdl -Dname=strepto -Dfqmap=strepto_lri_real.txt
#
# Genestrip skips a file that is already in place, so it is safe to repeat. About 1.5 GB in total.
