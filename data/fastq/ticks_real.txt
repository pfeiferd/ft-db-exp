# The eight real Nanopore tick runs NanoSim trains its error model on, from SRA study PRJNA790938 --
# the tick surveillance work the first Genestrip paper builds on. Ticks 1 to 4 are that study's
# "NASenrich" runs, ticks 5 to 8 its "NASdeplete" ones; its "control" and Illumina "16S" runs of the
# same ticks are deliberately not listed here.
#
# This is an ordinary Genestrip fastq map, so the goal `fastqdownload' fetches every entry whose
# second column is a URL. With -ll the files land in the common fastq directory, i.e. data/fastq,
# named after their key: data/fastq/tick1.fastq.gz .. tick8.fastq.gz. That is exactly what
# make_fastqs.sh expects, and it is the same name the map would refer to if the files were local, so
# nothing downstream has to know where they came from.
#
#   mvn exec:exec@fastqdl -Dname=tick-borne -Dfqmap=ticks_real.txt
#
# make_fastqs.sh tick-borne runs that itself for whatever is missing. Genestrip skips a file that is
# already in place, so it is safe to repeat; about 3.2 GB in total.
#
# Not to be confused with seventicks.txt beside it, which maps the same runs to their local files for
# *classifying* the real reads, as the first paper did, and leaves tick5 out because KrakenUniq hung
# on it. This map declares all eight, since the simulation trains on each of them in turn.
#
# The URLs are NCBI's own SRA fastq endpoint, under the host the original genestrip-db-exp project
# used for exactly these eight runs. It serves gzip, despite the URL not saying so, which is
# what makes the .fastq.gz naming correct -- Genestrip assumes gzip by default (alwaysAssumeGzip) and
# names the download after the key rather than the URL, so the file names do not depend on the form
# of the URL at all. Two alternatives, should this host be unreachable from a given network:
#
#   trace.ncbi.nlm.nih.gov       the same endpoint under NCBI's public host name; substitute it for
#                                www.be-md.ncbi.nlm.nih.gov below and nothing else changes
#   ftp.sra.ebi.ac.uk            ENA, which mirrors the identical SRA runs as
#                                https://ftp.sra.ebi.ac.uk/vol1/fastq/SRR172/0NN/<acc>/<acc>_1.fastq.gz
#                                where NN is the last two digits of the accession. Verified to serve
#                                the correct read counts, but not reachable from every network.
#
